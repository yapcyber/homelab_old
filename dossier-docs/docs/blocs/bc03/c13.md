# BC03 · C13 — Plan périodique de restauration

**Statut : Solide — tests réalisés 22 juillet et USB, logs conservés.**

## Intitulé

**Énoncé du référentiel.** Établir un plan périodique de restauration et de vérification d'intégrité des données sauvegardées.

**Critère d'évaluation.** Les tests des procédures de restauration sont probants : datés, tracés et concluants.

## Interprétation

Un test probant n'est pas une vérification automatique d'intégrité seule. C'est : restaurer réellement dans un environnement contrôlé, vérifier que les données sont exploitables, documenter la date et le résultat.

## Réponse

**Origine de l'acquisition.** J'ai établi et exécuté des tests de restauration réels sur la chaîne 3-2-1-1-0 du homelab.

**Contexte.** Deux restaurations complètes documentées : (1) **22 juillet 2024** : restauration de Nextcloud depuis dépôt restic hors site (dumps déchiffrés, base chargée, interface webui validée), durée 1h30, logs conservés; (2) **Restauration USB LUKS** : tirage des archives depuis clé chiffrée, déchiffrement du tar, restauration PostgreSQL, vérification des tables, durée 45 min, date enregistrée.

Plan périodique formalise les restaurations : (1) **Mensuel** : test applicatif complet (restauration dans conteneur éphémère, vérification des schémas et données métier, comparaison avec source vive si possible). (2) **Quotidien** : vérification d'intégrité automatique (sha256sum dumps locaux, restic check hors site, alerte ntfy en cas d'écart). (3) **Trimestriel** : test de restauration depuis USB (procédure documentée, pas toujours exécuté mais clairement tracé quand réalisé).

Chez Dupont, audit de la procédure PRA (plan de restauration applicatif) et participation à un drill trimestrial.

## Preuves

- Journal daté restauration 22 juillet (entrée, durée, résultat : OK, logs stdout/stderr).
- Journal daté restauration USB LUKS (date, machines concernées, résultat).
- Configuration restauration périodique (crontab ou systemd timer, script, résultats).
- Procédure test mensuel (étapes, environnement, critères de succès).
- Logs du contrôle quotidien d'intégrité (exemple d'une semaine, alertes si anomalies).
