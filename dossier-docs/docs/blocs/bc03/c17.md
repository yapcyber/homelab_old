# BC03 · C17 — Protections assurant la disponibilité (PCA)

**Statut : Solide — stockage partagé, sauvegardes testées, supervision.**

## Intitulé

**Énoncé du référentiel.** Déployer les mécanismes techniques assurant la disponibilité et la continuité : réplication, sauvegardes, redondance, supervision.

**Critère d'évaluation.** Les données répliquées et sauvegardées sont accessibles et opérationnelles, validées par des tests.

## Interprétation

Montrer que les données existent en **plusieurs exemplaires exploitables** et que les mécanismes de reprise **fonctionnent réellement** (pas de théorie).

## Réponse

**Origine de l'acquisition.** J'ai implémenté les mécanismes de disponibilité du homelab : stockage partagé, sauvegardes, supervision.

**Contexte.** Trois mécanismes concourent : (1) **Stockage NFS partagé** (TrueNAS) permettant la migration de VM entre nœuds Proxmox. Migrations réelles exécutées : p.ex. Nextcloud migré de pve1 vers pve2 (downtime ~2 min, données intactes). (2) **Sauvegardes multi-niveaux** : dumps chiffrés locaux (7j roulement), restic hors site (rétention 7/4/6), USB LUKS hors ligne. Tests de restauration probants (voir C12-C13 : restauration 22 juillet depuis restic réussie, USB LUKS OK). (3) **Supervision** : Uptime Kuma alerte sur services down, Wazuh vérifie fraîcheur des backups quotidiens, ntfy notifie de toute anomalie.

Disponibilité globale : si une VM crash, elle relance ailleurs (HA). Si donnée corrompue, restauration du dépôt (sauvegardes intègres + testées).

Chez Dupont : audit PCA/PRA incluant validité des sauvegardes (audit ISAE 3402).

## Preuves

- Logs migrations Proxmox (VM, source, destination, durée downtime).
- Configuration NFS (fstab, montage partagé, permissions).
- Logs et résultats tests restauration (C13 partage la preuve).
- Configuration supervision : Uptime Kuma (services moniteurés), Wazuh (alertes backups).
- Chronologie incident résolu par restauration (si applicable).
