# BC03 · C4 — Sécuriser les transactions numériques

**Statut : Solide — reverse proxy, JWT, chiffrement TLS.**

## Intitulé

**Énoncé du référentiel.** Sécuriser les transactions numériques (accès aux données, paiements, communications sensibles) via des procédures de contrôle d'accès structurées.

**Critère d'évaluation.** Des procédures formalisées contrôlent l'accès aux données et aux transactions critiques.

## Interprétation

Montrer le **chemin d'une transaction** du client au serveur : authentification, autorisation, chiffrement, audit. Pas seulement « TLS est activé », mais « qui peut lire quoi et comment ».

## Réponse

**Origine de l'acquisition.** J'ai sécurisé les flux d'accès aux données chez Dupont (bases de données, fichiers partages) et sur mon homelab (APIs, accès base de données).

**Contexte.** Chez Dupont, la politique d'accès aux données sensibles (dossiers RH, fiches clients, données de paie) repose sur : (1) **authentification LDAP + MFA** via Authentik SSO, (2) **autorisation par groupe AD** (ex. groupe « Paie » accède à \\srv\Paie, groupe « RH » à \\srv\RH), (3) **chiffrage de transit** TLS 1.2+ obligatoire pour tous les flux sensibles (WebDAV, LDAPS), (4) **journalisation centralisée** (logs d'accès, modifications de permissions) dans Wazuh. Sur le homelab, les APIs de service (Nextcloud, NetBox, Jellyfin) utilisent **JWT** pour les appels de machine à machine, avec durée de vie courte (15 min) et rotation automatique. Accès base de données : socket local uniquement, authentification par schéma (chaque application a un utilisateur de base dédié avec permissions restreintes au schéma / tables pertinentes).

Paiements (Dupont) : passerelle de paiement PCI DSS (Stripe, Square, ou provider externe) isolée du SI interne par proxy, sans stockage de données de carte en interne.

## Preuves

- Schéma authentification → autorisation → chiffrage pour 1 flux de données sensibles (ex. accès dossier RH).
- Configuration LDAP Authentik (groupes, résolution).
- Règles d'autorisation AD (groupes → ressources).
- Configuration TLS/LDAPS (certificat, version min, cipher suites).
- Exemple JWT (payload anonymisé, durée de vie, clé secrète : absent de la preuve).
- Politique accès base de données (utilisateurs, permissions par schéma).
- Preuve de journalisation (logs d'accès anonymisés).
