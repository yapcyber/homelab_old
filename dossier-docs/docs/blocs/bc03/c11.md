# BC03 · C11 — Criticité de l'interruption (BIA)

**Statut : Trace à créer — tableau BIA (~70 % prêt).**

## Intitulé

**Intitulé (abrégé du référentiel).** Évaluer la criticité de l'interruption d'activité et produire des préconisations.

**Critère d'évaluation.** Le plan de reprise est priorisé, les délais d'interruption validés.

## Interprétation

Le critère attend une priorisation explicite : quels services d'abord, quels délais de reprise, quelle perte de données admissible — une vraie analyse d'impact, à mon échelle.

## Réponse

La voie retenue est une **BIA authentique sur le homelab** : un tableau d'une
page par service (impact d'une interruption, RTO, RPO, moyen de reprise). La
hiérarchisation réelle : le coffre de mots de passe et les configurations
d'infrastructure versionnées d'abord (reprise courte), puis les bases des
services familiaux, photos et fichiers, enfin les médias reconstructibles
(reprise longue). Environ 70 % du contenu existe déjà dans l'analyse HA
(criticité, RTO/RPO, dépendances). La transposition à l'entreprise s'appuiera
sur les réponses tuteur (PRA/PCA, criticité applicative), sinon en projection
assumée.

## Preuves et chemin de raisonnement

- Tableau BIA d'une page (service, impact, RTO, RPO, moyen de reprise).
- Questions tuteur en attente : localisation du PRA/PCA, définition de la
  criticité applicative, RTO/RPO existants.
