# BC03 · C18 — Sécurité cloud cohérente

**Statut : À confirmer — politique à rédiger (1 page).**

## Intitulé

**Intitulé (abrégé du référentiel).** Assurer un modèle de sécurité cohérent sur site et dans le Cloud.

**Critère d'évaluation.** La politique de sécurité du Cloud est définie.

## Interprétation

Le critère demande une politique **définie** : ce qui peut aller dans le cloud, ce qui reste interne, et à quelles conditions — formalisée, pas implicite.

## Réponse

La politique cloud personnelle reflète la pratique réelle : vont dans le
cloud le **DNS public** (Cloudflare), l'exposition du **seul portfolio** par
tunnel sortant sans port ouvert, et la **copie de sauvegarde chiffrée côté
client avant envoi** (dépôt restic — le fournisseur ne voit que du chiffré).
Tout le reste demeure interne, joignable uniquement par VPN. Conditions :
secrets chiffrés (SOPS/Age), MFA chez les fournisseurs. Côté Dupont : règles
cloud connues (MFA, restrictions de partage) et précautions prises sur mes flux
PowerAutomate (récupération finale manuelle des exports sensibles).

## Preuves et chemin de raisonnement

- Politique cloud d'une page, publiée (à rédiger depuis la pratique).
- Configuration expurgée de la copie hors site chiffrée côté client.
