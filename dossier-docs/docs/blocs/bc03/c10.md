# BC03 · C10 — Mises à jour automatisées des outils de sécurité

**Statut : Solide — CVSS policy, Tanium rings, patches testées.**

## Intitulé

**Énoncé du référentiel.** Automatiser les mises à jour et correctifs des outils et solutions de sécurité, en respectant une politique de priorisation.

**Critère d'évaluation.** Les outils de sécurité bénéficient de mises à jour systématiques et priorisées selon les risques.

## Interprétation

Montrer le **cycle complet** : politique (quels délais pour quelle criticité), outillage de déploiement automatisé, vérification post-patch. Pas juste « auto-updates activées ».

## Réponse

**Origine de l'acquisition.** J'ai appliqué la politique CVSS chez Dupont et géré les patches du homelab.

**Contexte.** Chez Dupont, **politique CVSS** : score ≥ 8 (critique) → déploiement Tanium dans les 7 jours, 6-7.9 (haute) → 14 jours, < 6 (moyenne/basse) → 90 jours. Outillage : **Tanium** déploie les mises à jour par rings (test sur 5 postes, puis 25%, puis 100%), journalisation de chaque déploiement (exécution, succès, échecs). Mon rôle : vérifier les vulnérabilités nouvelles en CVSS, lancer les déploiements Tanium dans les délais, et vérifier post-patch (scan des systèmes concernés).

Homelab : **baseline `unattended-upgrades`** sur chaque VM (sécurité d'abord, reboot si nécessaire). Fenêtre de patch hebdomadaire : snapshot pré-patch via Proxmox, exécution du playbook Ansible `patch.yml`, puis tests de smoke (services redémarrés, connectivité remontée). OpenVAS scans toutes les deux semaines pour contrôler qu'aucune vulnérabilité n'a échappé au patching.

## Preuves

- Politique CVSS formalisée (dates limite par score) anonymisée ou schématique.
- Captures Tanium : groupes de déploiement (rings), journal d'une exécution, taux de succès.
- Playbook Ansible patch.yml (snapshot + `apt update && apt upgrade` + redémarrage).
- Rapport de smoke test post-patch (services validés, connectivité réseau).
- Rapport OpenVAS (données avant/après patch, réduction de vulnérabilités).
