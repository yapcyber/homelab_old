# BC02 · C10 — Environnement de test permanent

**Statut : Solide.**

## Intitulé

**Énoncé du référentiel.** Organiser l'infrastructure pour l'intégration permanente d'évolutions logicielles avec chaîne de validation automatisée.

**Critère d'évaluation.** Un environnement de tests permet la mise en production continue, avec traçabilité de la validation.

## Interprétation

Décrire précisément ce qui est contrôlé **automatiquement**, ce qui reste **manuel**, et le signal qui déclenche un **retour arrière** — sans présenter le déploiement bout en bout comme automatique tant qu'il ne l'est pas.

## Réponse

**Origine de l'acquisition.** J'ai mis en place une chaîne d'intégration et de déploiement sur mon homelab avec plusieurs briques.

**Contexte.** (1) **Détection automatisée** (Renovate) : scan quotidien des registres Docker pour les nouvelles versions d'images, ouverture automatique de PR avec les changements. (2) **Validation pré-merge** (CI GitHub Actions) : shell-linting, validation Docker Compose, vérification Markdown, build du portfolio. Aucune modification n'est deployée si la CI échoue. (3) **Snapshot avant mise à jour** : snapshot LVM horodaté de tous les volumes avant fusion. (4) **Stratégie de déploiement** : une version majeure à la fois (ex. Wazuh 4.13 → 4.14, jamais 4.13 → 5.0). Après déploiement, smoke test : vérifier que le conteneur redémarre et le service est accessible. (5) **Retour arrière programmé** : restauration du snapshot Proxmox en cas d'échec détecté.

Le déploiement entièrement automatique de la fusion à la production est un **chantier en cours**, décrit comme tel. CV-as-Code est partiellement en place (code généré OK, intégration en cours).

## Preuves

- Fichier renovate.json (configuration, registres surveillés, stratégie d'update).
- Exemple de PR Renovate (diff montrant images à jour).
- Historique de PR mergées (3-5 PR Renovate).
- Capture d'une exécution réussie de la CI GitHub Actions (tous les jobs en vert).
- Snapshot Proxmox horodaté (lvscan ou Proxmox UI).
- Procédure de smoke test (checklist : conteneur, logs, accessibilité, supervision).
- Exemple de retour arrière (logs de restauration, redémarrage du service).
