# BC02 · C7 — Superviser l'infrastructure

**Statut : Solide — captures d'incident à rassembler.**

## Intitulé

**Intitulé (abrégé du référentiel).** Superviser l'infrastructure et le patrimoine applicatif.

**Critère d'évaluation.** Les difficultés sont identifiées et les solutions apportées.

## Interprétation

Le critère demande une difficulté réelle **et** sa résolution, pas un tableau de bord à plat : montrer la détection, le diagnostic et la correction.

## Réponse

**Détection active via Uptime Kuma.** L'infrastructure est supervisée par un outil centralisé (Uptime Kuma) qui teste tous les 30 secondes la disponibilité des services critiques (Jellyfin, Nextcloud, OpenWrt, portfolio). Les indisponibilités déclenchent une **notification Slack/ntfy** en temps réel.

**Incident majeur : cascade de fermetures VM (2026-04-XX).** Symptôme : Uptime Kuma remonte une vague de services tombant quasi-simultanément (Jellyfin -> NetBox -> Nextcloud -> OPNsense, intervalle < 1 minute). Diagnostic : accès Proxmox -> Dashboard nœud pve1 affiche une **surallocation RAM** (36 Go VM allouée contre 32 Go physique), hyperviseur tue les VM pour libérer la mémoire. Solution : migration d'une VM vers pve2 (20 min arrêt accepté pour une migration à chaud). Vérification post : état nominal, services revenant en ligne progressivement. Durée totale : 47 minutes d'indisponibilité partielle.

**Incident secondaire : NetBox arrêté depuis 3 semaines (2026-06-XX).** Uptime Kuma le détecte automatiquement après une fenêtre de test manquée. Cause : politique de redémarrage défaillante (pas de `restart: always` en Docker). Correction : ajout du flag, redémarrage.

**Alertes mises en place.** Seuils supervisés : (1) CPU nœud > 80 % pendant 2 min -> alerte orange. (2) RAM utilisée > 85 % -> alerte rouge. (3) Disque stockage NFS > 90 % -> alerte. (4) Conteneur arrêté -> notification.

## Preuves et chemin de raisonnement

- **Capture Uptime Kuma** : tableau de bord montrant les 8-10 services et leur statut au moment de l'incident (vert/rouge/dégradé).
- **Chronologie de l'incident** : 14:22 Jellyfin rouge -> 14:23 NetBox rouge -> 14:24 Nextcloud -> 14:25 reprise progressive ; graphique temporel montrant la chute en cascade.
- **Capture Proxmox Dashboard** : nœuds avec charges (pve1 RAM rouge, pve2/pve3 vert), identificateur VM surchargée.
- **Graphique Grafana** : courbe RAM utilisée (pve1 > 100 % théorique) avant/après migration.
- **Notification ntfy** : capture du message d'alerte reçu, avec timestamp.
- **Politique de redémarrage Docker** : extrait du Compose montrant `restart: always` appliqué.
